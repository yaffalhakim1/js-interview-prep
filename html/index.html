How to use this

1. Read the idea first

Each topic starts with the idea, not the syntax. If you can explain the idea, the code writes itself.

2. Run the code

Blocks with a Run button work in the page. Change them. Break them on purpose.

3. Answer the questions

Every page ends with a few questions. If an answer surprises you, read that part again.

4. Say it out loud

Interviewers score how you explain things. The Say this in an interview boxes give you the words to practise.

5. Take it offline

The same course is available as a PDF and as markdown, for reading without a browser.

What the 35 minutes look like

Every coding interview follows roughly this shape. The full version is in How to run the interview.

MinutesWhat you doWhy it scores
0–2Introduce yourself in under a minute. Ask what the team builds.Shows you can read the room.
2–6Ask questions: input, runtime, browsers, edge cases.Shows knowledge, and stops you rewriting later.
6–9Say your plan, and which tradeoff you picked.They score the thinking before the code.
9–25Write it, saying why as you go. Remember the callback's this.Shows engineering skill.
25–31Read it again for typos, then test the normal case and the edges.Testing is one of the scored skills.
31–35Say what you left out and how you would add it.Knowing the limits is a senior signal.
